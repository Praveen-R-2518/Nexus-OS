## Social posting: publish + schedule contract (2026-07-15)

The app now drives publishing directly (no approval queue). Two n8n workflows complete the loop:

**WF8b — Social Post Publishing** (webhook `POST /webhook/publish-social-post`, id `VZ9ZaA1S2JxSAeGQ`)
- Trigger payload from the app (`app/api/posts/publish/route.ts`): `{ orgId, postId, platforms[] }`.
  The app flips the post to `publishing` before calling. If the webhook is non-OK, the app marks
  the post `failed` so it does not stay stuck.
- `GET {NEXUS_APP_URL}/api/internal/n8n/social-post?organization_id=&post_id=` returns a **signed**
  `media_signed_url` (Instagram cannot fetch private storage paths) plus `composed_captions`
  (caption + hashtags). Tokens still come from
  `GET /api/internal/n8n/social-credentials`. **No Supabase REST.**
- Per-platform publish: Instagram waits for the media container `FINISHED`; Facebook posts a photo
  when media exists; X may append the media URL; LinkedIn UGC is supported. Terminal status is
  always `POST /api/internal/n8n/post-result`. Same-workflow Error Trigger writes `failed` if a
  node throws before Finalize.
- Set the app env `N8N_SOCIAL_PUBLISH_WEBHOOK_URL` to
  `https://knurdz3o.app.n8n.cloud/webhook/publish-social-post`.

**WF8d — Social Post Scheduler** (Schedule Trigger every 5 min, id `47BO0agxAJGizttR`)
- `GET {NEXUS_APP_URL}/api/internal/n8n/scheduled-posts` (Bearer `N8N_INGEST_TOKEN`) — this endpoint
  **atomically claims** due posts (`status=scheduled AND scheduled_at<=now` → flipped to `publishing`)
  and returns them, so overlapping polls never double-publish.
- `Expand Posts` (one item per post) → `Trigger Publish` (POST
  `{{ $vars.N8N_SOCIAL_PUBLISH_WEBHOOK_URL }}` — n8n Variable, not `$env`, per the Cloud
  restriction noted below — with `{ orgId, postId, platforms }`) → WF8b publishes each.
- **Inactive on purpose (2026-09-01)** until a real post is scheduled. Composer **Schedule** now
  stamps `approval_status`/`approved_at` via `createPost()`, so the claimer will pick those rows up
  once this workflow is re-activated.

**Internal endpoints added (app):** `GET /api/internal/n8n/scheduled-posts` (claim due posts) and
`POST /api/internal/n8n/post-result` (terminal `published`/`failed` writeback — the browser can't
write these). Both Bearer `N8N_INGEST_TOKEN`.

App env required: `N8N_SOCIAL_PUBLISH_WEBHOOK_URL` (app → WF8b). n8n env required:
`NEXUS_APP_URL` + `N8N_INGEST_TOKEN` + `N8N_SOCIAL_PUBLISH_WEBHOOK_URL`, plus each platform's
publishing credential on WF8b.

## Notes

- `wf1/wf3/wf4_*.json` are **snapshots exported from the live instance** after the 2026-07-12
  tenant-stamping (2.4) + autopilot-rewire (1.5) edits, then re-wired again 2026-07-17 (second
  pass, see above). They are NOT generated by `build_n8n_workflow_exports.js` — if you edit these
  workflows live again, re-export the snapshot (via the n8n MCP `get_workflow_details` or the n8n
  UI export) to keep the repo in sync.
- **Live activation status (2026-09-03):** `wf0a`, `wf0d`, `wf0f`, `wf1`, `wf2`, `wf3`, `wf4`,
  `wf5`, `wf8b`, `wf9`, Approval Trigger are **active**. `wf8c`, `wf8d`, `wf0e`, and leftover WF8a caption
  generation are **inactive** (quota / superseded). Real Gmail *sending* is still blocked on the
  `gmail.send` OAuth scope. WF4/WF5 no longer call `supabase.co` from n8n.
- Internal `/api/internal/n8n/*` routes **exist in this checkout** (including `scheduled-posts`,
  `social-post`, `followups/drain`, `daily-report`). Production WF8d was already reaching
  `https://nexusos.knurdz.org/api/internal/n8n/scheduled-posts` before it was deactivated. The
  older “issue-fix2 not on main / 404” warning is stale for this tree.
- HTTP nodes that call Supabase REST use the instance's **Supabase custom auth** credential —
  re-select it on import. Nodes that call the Next.js app (`Autopilot Send (policy-gated)`) use
  header-based `Authorization: Bearer {{ $vars.N8N_INGEST_TOKEN }}` — n8n Cloud blocks `$env` in
  node expressions, so this must be an n8n **Variable**, not an environment variable. Set
  `NEXUS_APP_URL` + `N8N_INGEST_TOKEN` as n8n Variables (Settings → Variables).
